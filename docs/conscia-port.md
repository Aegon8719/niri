# Conscia 布局移植

此版本以相邻 `Conscia` 仓库的 Main/Reel 策略替换 niri 的默认滚动列布局。
保留 niri 的 DRM/Wayland 后端、输出热插拔、独立工作区、配置解析、IPC、
屏幕共享、锁屏和 layer-shell。每个 niri 工作区拥有独立的 Conscia 状态。

## 代码来源与接入

- `src/layout/scrolling/conscia/core.rs`：Conscia `crates/reel-core/src/lib.rs`。
  保留窗口队列、主窗口、Main 分组、Reel 分组、分割比例、切换及最小化规则；
  增加了供 niri 跨工作区传输分组使用的导入入口。
- `geometry.rs`：Conscia `crates/layout/src/lib.rs`，仅改变模块引用。
- `scene.rs`：Conscia `crates/renderer/src/lib.rs`，仅改变模块引用。
- `mod.rs`：将 Conscia 模型与 niri 的 Tile、窗口配置和工作区容器连接。
- `tiling.rs`：Main 分组的持久化 Dwindle 分割树、拖拽交换与四边贴靠、分支比例及跨工作区传输。
- `src/input/conscia.rs`：鼠标事件仲裁；缩略图的按键不会传给应用。

niri 的 Column 保留为窗口组的传输容器，其顺序由 Conscia 模型重建，
不再决定默认窗口的二维布局。无新增 Cargo 依赖，也不依赖运行时访问相邻仓库。

## 行为

每个屏幕始终至少保留两个工作区，即使所有应用均已关闭。切换空工作区、
关闭后台窗口或迁移工作区时也保留此下限；多余的未命名空工作区仍按动态规则回收。

Main 占据大区域，Reel 占据其侧边。整数求解器选择 3 或 4 个缩略图槽位，
保留 Conscia 的尺寸取整、半像素居中和极小工作区退化规则。
工作区的小窗列为空时，Main 自动占满可用工作区，不预留 Reel 空间；
这既适用于单个窗口，也适用于所有窗口均已加入 Main 分屏的情况。
出现独立的 Reel 窗口组后恢复 Main/Reel 布局，全部纳入 Main 或关闭后再次铺满。
此行为保留桌面面板，不改变显式最大化/全屏状态；瞬态对话框不计入窗口数。
新应用默认获得焦点并进入右侧主区域，原主窗口组移到左侧 Reel 最前端，
同时将 Reel 滚动位置归零。新窗口加入不再交替翻转左右；显式后台打开规则仍保留。
手动提升小窗仍可翻转小窗列，下次打开新应用时恢复左侧 Reel；移除 Mod+R 默认绑定。
Reel 窗口配置为 Main 尺寸，显示时保持宽高比缩放；不把客户端改成缩略图尺寸。

提升 Reel 窗口时，当前 Main 连同分组和分割比例进入 Reel 前端，Reel 翻到另一侧。
普通提升与分组编辑使用 Conscia 的 220ms smoothstep 插值；隐藏端点以淡入淡出处理。
关闭主窗口时，保留关闭前的窗口位置，接替的小窗在 220ms 内移动并放大到主区域；
其余小窗同步补位，只剩一个窗口时平滑展开到整个可用工作区。
新应用使用相同的 220ms smoothstep 动画，从工作区右边缘外滑入主区域，
原主窗口组同步缩小并移入左侧 Reel，其余小窗同步补位。
首个窗口滑入后占满可用工作区；后台打开和瞬态对话框不使用此入场动画。
工作区尺寸变化和展开窗口沿用 Conscia 的直接布局更新。
`animations { off; }` 仍可关闭切换动画。

滚轮与 Reel 上的触控手势只浏览缩略图，不改变窗口队列或键盘焦点。
高精度滚动累计到整槽后提交，反向滚动或 140ms 间隔清空余量。
滚动抵达小窗列顶部或底部时不播放动画；已处于边界时再次向外滚动，才播放 300ms 的轻微压缩回弹，
最大位移 32 个逻辑像素；不改变窗口顺序或焦点，也不会把缩略图移出工作区。
左键提升缩略图，右键把它加入 Main；Main 内部的分割线可直接拖动。
小窗列按整个窗口组槽位响应点击，组内分屏之间的 gap 与窗口内容执行相同操作。

### 主区域内的 Dwindle 平铺

Main 分组使用持久化二叉分割树。加入分组的窗口按当前焦点子区域的长宽选择
左右或上下分割；拖拽指定的方向和分割比例会保留，关闭窗口只折叠对应分支。
分组移入 Reel、再次提升或整组移到其他工作区时保留内部排列。

- 在主区域按住鼠标左键拖动标题栏；移动超过 8 个逻辑像素才开始拖拽。主区域普通右键菜单保留，右键加入 Main 只作用于小窗列。
- 分屏窗口也支持直接拖动标题栏贴靠；平铺窗口标题栏不再回退到原生列滚动、移出窗口或切换浮动。
- 拖到另一窗口中央区域，交换两者位置；拖到左、右、上、下边缘，按该方向贴靠并分割。
- 将半屏窗口拖到对侧等大分组的中央，可与该分组整体交换；分组内两个四分之一窗口的排列和比例保留。
- 拖动中只显示当前窗口落点的半透明圆角占位框，以 120ms 动画淡入、淡出；占位位置直接使用待提交布局的精确矩形，其他窗口保持原位置和尺寸。
- 松手后才提交分割树，所有受影响窗口统一播放 220ms 重布局动画。
- 按 Esc 或拖出主区域松手取消，保留原布局；切换工作区、锁屏、弹出对话框和工作区几何变化也会取消拖拽。
- Main 拖拽期间屏蔽屏幕边缘面板、热角和鼠标跟随焦点，不允许小窗激活或最小化请求将整个 Main 分组换入小窗列。
- 全局移除热角、鼠标跟随焦点、拖拽边缘滚动／工作区切换和拖拽悬停自动激活；配置不能重新启用这些路径。点击、快捷键和 Main 内部贴靠仍可用。
- VMware 环境下，app-id 与标题均为 `vmware-user` 的边缘拖放辅助窗口只保留协议生命周期，不加入布局、焦点、任务列表或渲染。实际事件记录显示它短暂映射后抢占 Main，再于销毁时恢复原分组；该问题与热角和 DMS 无关。
- 直接拖动分割线调整比例；宽高快捷键调整当前窗口对应方向最近的分割，保留其他分支。

Mod 在桌面会话中为 Super。拖拽整理仅作用于 Main 内部，不改变新应用进入右侧、
旧主窗口组移入左侧 Reel 的外层策略。此实现采用 Dwindle 的分割交互，不引入 Hyprland 配置语法。

Transient 对话框不进入 Reel，按所属 Main 窗口的可见性显示，在 Main 区居中。
最小化把窗口送到 Reel；唯一的窗口最小化后保留缩略图，点击或 Tab 可以恢复。
普通窗口初始映射不再使用 niri 的浮动启发式；显式的 niri 浮动操作仍属于兼容功能。

## 快捷键与动作兼容

只修改仓库内的默认配置模板，不改写用户已经安装的配置文件。
保留现有配置和 IPC 动作名称，默认配置使用以下映射：

| 默认按键 | 保留的 niri 动作 | Conscia 行为 |
| --- | --- | --- |
| 单独短按两次 Super | 输入层识别，启动 DMS spotlight | 打开应用启动器 |
| Mod+Return | spawn alacritty | 启动终端 |
| Mod+grave（反引号） | show-hotkey-overlay | 显示快捷键面板 |
| Mod+Tab | focus-column-right | 提升 Reel 前端组 |
| Mod+F | maximize-column | 最大化主窗口：整个 Main 分组铺满可用桌面，再按恢复 |
| Mod+BackSpace | toggle-column-tabbed-display | 释放所有额外 Main 窗口 |
| Mod+Q | close-window | 关闭当前窗口 |
| Mod+Alt+方向键 | main-focus-left/right/up/down | 按几何方向切换 Main 平铺焦点 |
| Mod+Shift+方向键 | main-swap-left/right/up/down | 与指定方向的相邻窗口交换位置 |
| Mod+Ctrl+方向键 | set-column-width / set-window-height | 以 5% 步长调整平铺尺寸 |
| Mod+J | main-toggle-split | 切换当前窗口最近分割的水平／垂直方向 |
| Mod+Shift+J | main-swap-split | 交换最近分割两侧的整个分组，保留内部树 |
| Mod+Up / Mod+Down | focus-workspace-up / focus-workspace-down | 上一个／下一个工作区 |
| Mod+1 | screenshot | 区域截图 |
| Mod+L | DMS lock | 锁定屏幕 |
| Mod+Escape | quit skip-confirmation=true | 退出会话 |

移除 Mod+Shift+Tab 与 Mod+T 的默认绑定。快捷键浮层不在登录时自动弹出，
可用 Mod+反引号手动打开；按配置中的功能顺序展示中文 `hotkey-overlay-title`。
双击 Super 只接受两次单独短按，组合键、鼠标按键或滚轮会取消识别；锁屏和快捷键抑制期间不触发。
工作区、输出切换以及窗口/组移到其他工作区的动作继续通过 niri 的原有接口。
横向移动列和居中列动作映射为翻转 Reel；纵向移动动作浏览 Reel；
宽高设置动作调整当前窗口相应方向的最近分割比例，不恢复旧的无限滚动列算法。

## 窗口装饰与间距

Main/Reel 使用 niri 原生窗口装饰，当前焦点窗口显示 focus-ring，圆角由
`geometry-corner-radius` 与 `clip-to-geometry` 控制。整数求解器及 Dwindle 分割树
先算原始槽位，再向内扣除 `ceil(gaps / 2 + focus-ring.width)`；边框继续从剩余区域内扣除。
原始槽位和分割比例保持不变，渲染、客户端尺寸、鼠标命中和落点预览使用扣除后的区域。
Main 整组最大化保留分屏和 DMS 状态栏，显式应用全屏沿用原有无间距行为。
缩略图按最终显示比例补偿圆角半径，因此 Main 与 Reel 中的窗口具有相同的可见圆角。
焦点描边默认启用蓝紫渐变。用户配置最后加载 `conscia/appearance.kdl`，避免 DMS 配色覆盖。
平铺快捷键采用 Hyprland Dwindle 的方向操作、切换分割和交换分组思路，具体绑定为了保留
Super+Up/Down 工作区切换而调整；参见 https://wiki.hypr.land/configuring/layouts/dwindle-layout/ 。
